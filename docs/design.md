# Design decisions to discuss

## Desktop + API

Swing provides a desktop app using the JDK. The trade-off is a basic visual style and manual layout.
The client calls HTTP; only the API holds database credentials. A hosted API can support multiple
devices later. The desktop owns an embedded backend on an available loopback port and closes
it on quit, without affecting external servers. `ATLAS_API_URL` enables external-server mode.
PostgreSQL is still a separate prerequisite; the app does not package a database engine.

Both entry points share one Maven project to simplify setup. The desktop profile selects its main
class. Its executable includes backend libraries and is larger than necessary; separate Maven
modules become useful once the client grows.

## Packages by feature

ExpenseController owns HTTP/DTO conversion; ExpenseService owns operations and transactions;
ExpenseRepository queries PostgreSQL; Expense maps a row. Request/response records are the public
contract. No custom repository wrapper or service interface is needed yet.

## Persistence

Expenses are the source of truth. Flyway owns schema; Hibernate validates mappings. Applied V1
remains unchanged. V2 indexes date/id for stable pagination. Events and a timeline can follow when
we have another domain to integrate.

## Money and dates

BigDecimal and NUMERIC(19,2) preserve decimal amounts. This version supports exactly two fractional
digits regardless of currency. Other currency conventions need a deliberate future schema change.
Totals are separate per currency by default, with optional purchase-date conversion described below.
LocalDate is purchase day; Instant is creation time.

## Validation, queries and updates

Request DTOs validate inputs; SQL also enforces basic constraints. IDs/timestamps are generated by
the application. Desktop validation gives feedback but the API is authoritative.
Filters are inclusive dates and exact category ignoring case. PUT replaces all editable fields.
Offset pagination has a stable UUID tie-breaker. Concurrent edits currently use last-write-wins;
add optimistic locking when multiple editors become relevant.
Totals currently sum matching entities in Java for readability. Replace with grouped SQL for large
histories. A row count and totals use separate reads and may differ briefly during concurrent writes.

## Next product decision

Should Atlas be an offline personal desktop tool, or a cloud-synced service? Offline favors an
embedded database and local packaging; cloud fits the current API/PostgreSQL architecture.
Choose before adding authentication or sync. V0.1 is single-user and binds to loopback.
For the proposed Mac + iPhone product, the recommended direction is accounts with a hosted API.
Both clients call the same backend. Offline editing can follow after online access works.
Swing is a Mac/desktop prototype, not an iPhone client framework; reconsider the client stack
before investing heavily in UI polish (native SwiftUI versus a shared mobile/desktop framework).
Before hosting: accounts, password hashing, authentication, ownership checks, authorization tests,
then deployment/observability. Public Mac distribution also needs signing/notarization.

Categories come from a shared catalogue enforced by the API and selected through dropdowns.
Existing legacy rows remain unchanged. Add a timeline when notes/goals
exist. Redis, background queues and AI should follow measured workloads or product requirements.

## Purchase-date conversion

The default is separate totals. Users can opt into a saved historical-conversion view and choose
a target currency. Original monetary records remain authoritative and unchanged.
Frankfurter supplies reference rates for each currency pair and purchase date. The actual
observation date is retained. A prior rate up to seven days earlier accommodates non-publishing
days; later rates are rejected. Stored snapshots are reused for repeatable calculations.
Each expense is rounded HALF_EVEN to two decimals before summing. Incomplete conversion returns
no combined amount. The UI falls back to original totals with an explicit notice.
External calls happen after reading expenses, outside a long-lived database transaction.
The network lookup budget is bounded; the cache fills over successive requests for long histories.

Preferences are saved locally on the desktop. Account-level preferences can replace this when
identity is implemented. Only pairs/dates go to the provider, not amounts or notes.
Provider documentation: https://frankfurter.dev/ .

## Reimbursements and net spending

Reimbursements are separate positive, received-money records linked by expense and currency.
The database enforces the link with a composite foreign key; the service locks the expense row
before every reimbursement/expense mutation, serializing checks of the aggregate repayment cap.
The original amount is retained. Incompatible edits and expense deletion return 409 rather than
silently rewriting the ledger. Mistaken reimbursement entries may be explicitly removed.
Bulk reimbursement totals avoid a per-expense query when mapping pages/report rows. Report reads
use repeatable-read snapshots for the parent values and reimbursement sums.

Purchase-based reporting attributes all received repayments to the original purchase date. This
restates earlier net costs, deliberately differing from a future cash-flow/account-balance view.
Converted totals convert each net purchase cost at its original purchase-date reference rate.
Fully reimbursed purchases need no rate lookup. A financial cash-flow report would need the actual
reimbursement-date rates separately; the current report does not claim to provide that.

Insights group original currencies independently and compare adjacent equal-length periods.
They report category shares, zero-filled daily/monthly net trends, and daily averages. Zero previous
spending produces a null percentage change rather than an infinity or misleading percentage.
The first version aggregates bounded (<=366-day) intervals in Java for readability. Move to grouped
SQL when measured data sizes justify it. Import design is in `iphone-import-plan.md`.
